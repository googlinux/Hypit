## Threat Model

Hypit is a local Node.js video-authoring CLI and browser Studio with extensible source packages, a persistent local runtime, local media subprocesses, and optional hosted generation through HypiHub. The launcher separately dispatches Studio or the video CLI (bin/hypit.mjs:21-45). A runtime is selected explicitly with --runtime or through the project's .hypit/runtime pointer; dataRoot is resolved relative to that runtime profile (packages/cli/src/main.ts:181-191; packages/project-context-node/src/runtime-selection.ts:25-34,64-75; packages/runtime-local/src/config.ts:263-272). The initial profile selects HypiHub at https://hypit.ai, local media, and local HyperFrames (packages/video-cli/src/distribution.ts:26-46). Normal build execution, explicit provisioning, doctor, pricing, capture, Studio, optional WhisperX, and CI publication have different network behavior. This is an architecture map of commit 18c0e6a222b28086d95829e4f822d0c17e2a60a7, not completed vulnerability-audit coverage.

### Assets

- Author source, referenced images/audio/video, generated output and transcription content. Hosted operations send compiled requests and selected reference media to the configured HypiHub service and its negotiated upload destination (packages/provider-hypihub/src/provider.ts:397-448; packages/provider-hypihub/src/upload.ts:393-415).
- HypiHub account authority: the default credential reference is os/hypihub.oauth. OS storage uses service hypit, macOS Keychain or Windows Credential Manager; Linux has no default OS backend. - Host-user execution authority and installed dependencies. ### Trust Boundaries

- Runtime configuration controls provider selection, base URL, executable configuration and credential references. The normal HypiHub adapter checks for HTTPS or a localhost/127.0.0.1 hostname, then passes the selected configuration to the provider; the directly exported createHypiHubProvider library factory separately normalizes a base URL without that adapter validation. Both default to https://hypit.ai/v1. Configuration and installed providers must therefore be trusted host inputs (packages/provider-hypihub/src/activation.ts:35-43,60-81; packages/provider-hypihub/src/provider.ts:59-64,512-530).
- Host to HypiHub: bearer-authenticated model, pricing, generation, speech, transcription, job-polling and upload-control requests go to the configured API base. OAuth consent and token endpoints use that base's origin. Token refresh is automatic when expired or after a supported 401 retry, and requires a writable credential slot (packages/provider-hypihub/src/provider.ts:134-145,297-300,335-349,441-448,570-585; packages/provider-hypihub/src/oauth.ts:58-99,109-115).
- HypiHub to storage destinations: API multipart is constrained to the selected service's /v1/files; direct multipart accepts HTTPS URLs returned by the service and sends media parts with checked length/checksum headers, without the API bearer header. Output downloads use URLs returned by HypiHub, so their concrete hosts cannot be determined from local source alone (packages/provider-hypihub/src/upload.ts:241-261,275-284,420-434; packages/provider-hypihub/src/provider.ts:152-161,397-401).
- Browser to Studio: the server binds 127.0.0.1, default port 5179. An early middleware checks a single loopback Host, matching Origin when supplied, Fetch Metadata, request-path shape, and requires matching Origin, JSON content type and a random per-session token for writes. It intentionally exposes selected workspace/package files and source-editing operations to this authorized local UI (packages/studio/start.ts:110-111,147-166; packages/studio/src/request-protection.ts:7-43).
- Browser OAuth callback to CLI: login starts an ephemeral listener at 127.0.0.1:\<port\>/callback, checks random state, uses S256 PKCE, opens the configured authorization endpoint and exchanges the code at the configured token endpoint (packages/cli/src/oauth.ts:39-103,105-129).
- Local runtime to local WhisperX: provider configuration is restricted to loopback HTTP; the default destination is http://127.0.0.1:8765. It stages a WAV below the OS temporary directory, sends its local pathname and language, checks service identity and bounds response size/time. The bundled service independently binds 127.0.0.1 and accepts JSON transcription requests subject to request/audio limits and configured input roots, defaulting to the temporary directory (packages/provider-whisperx-local/src/provider.ts:23,103-120,139-177; services/whisperx/src/hypit_whisperx_service/server.py:88-90; services/whisperx/src/hypit_whisperx_service/application.py:52-76; services/whisperx/src/hypit_whisperx_service/config.py:51-79).
- Explicit provisioning to external dependency supply chains: runtime up/programs up prepare selected dependencies; npm installs exact releases into host-owned version directories, uv uses frozen Python projects, NLTK preparation downloads missing punkt_tab, and model loading is delegated to WhisperX. These are expected automatic connections within an explicit provisioning/start action (packages/cli/src/commands/environment.ts:168-173,218-235; packages/runtime-host-node/src/packages.ts:76-105,131-149; packages/provider-whisperx-local/src/program.ts:128-135; services/whisperx/src/hypit_whisperx_service/resources.py:24-40; services/whisperx/src/hypit_whisperx_service/engine.py:107-111,123-129).
- Author-selected capture and rendering code has distinct authority. Capture scripts are imported as local Node modules and receive ordinary Puppeteer browser/page objects; capture URLs are explicitly navigated. HyperFrames browser programs intentionally execute supplied setup JavaScript, while the render server and browser controls are delegated to external @hyperframes packages (packages/video-cli/src/capture.ts:106,129; packages/browser-capture/src/index.ts:101-124; packages/hyperframes/src/browser-program.ts:63-65; packages/provider-hyperframes-local/src/capture.ts:38-39,122-123).
- Conditional library and CI interfaces remain separate: AwsLambdaJsonInvoker sends canonical JSON to a caller-selected Lambda function and optional endpoint with payload limits; no shipped runtime caller was established in this architecture pass. CI publishes artifacts and sends a documentation-change dispatch under separate workflow credentials (packages/transport-aws-lambda/src/index.ts:64-71,90-129; .github/workflows/publish-npm.yml:107-148; .github/workflows/sync-hypihub-docs.yml:24-53).
- Optional S3 ResourceStore/Result repositories use caller-configured bucket, region and endpoint with AWS SDK clients; first-party constructors do not add a hidden recipient. Default external-file access in the patched S3 Result repository fails closed (packages/resource-store-s3/src/client.ts:64-72; packages/resource-store-s3/src/store.ts:60; packages/build-result-s3/src/repository.ts:35-45).
- Explicit capture browser installation selects Chrome 153.0.8010.12 and PUPPETEER_CACHE_DIR or ~/.cache/puppeteer; absent browser causes normal capture to fail rather than silently install. yt-dlp runs from a frozen packaged uv project only for requested HTTP(S) video fetch, with staging, --no-playlist and timeout. Runtime HyperFrames preparation separately invokes its selected CLI browser ensure; exact external download hosts remain dependency-controlled (packages/browser-capture/src/browser.ts:7-18; packages/browser-capture/src/index.ts:101-124; packages/yt-dlp/src/download.ts:27-33,62-77; packages/provider-hyperframes-local/src/program.ts:31-50).

### Attacker Capabilities

- A remote service can control its response bodies, upload policies and result URLs; this does not initially grant access to local credentials or arbitrary local files. Destination handling and the amount of host authority conferred by response processing require separate validation (packages/provider-hypihub/src/provider.ts:152-161,397-401; packages/provider-hypihub/src/upload.ts:393-434).
- A web page can attempt browser requests toward loopback services but does not initially know Studio's random session write token. Studio's Host/Origin/Fetch Metadata guard is an independently enforced boundary (packages/studio/src/request-protection.ts:11-38).
- A local unprivileged process can attempt to access loopback listeners, but the architecture does not establish a separate OS-user authentication boundary for WhisperX. Do not equate loopback with authenticated caller identity (services/whisperx/src/hypit_whisperx_service/server.py:43-82,88-90).
- A malicious selected package, capture script or configured executable already runs with operator-granted host authority. Such trusted-code execution must not be presented as a sandbox escape without an independently enforced restriction (packages/package-loader-node/src/loader.ts:100-108; packages/video-cli/src/capture.ts:106; packages/runtime-local/src/programs.ts:107-112).
- Untrusted external media, website content, and provider results cross parser/browser/native-tool boundaries during explicitly requested work. Compromised dependency publishers or release infrastructure are separate supply-chain actors, not ordinary remote API callers.

### Security Objectives

- User-context objective: determine whether the selected source introduces hidden or unrelated outbound HTTP, SSH or other connections; distinguish explicit cloud/media/setup functions from unexpected background traffic.
- Preserve the configured provider/credential binding, send selected reference data only through intended provider operations, and keep credential material out of generated reports.
- Keep Studio writes restricted to its authorized local session and preserve source/result integrity (packages/studio/src/request-protection.ts:18-38).
- Maintain local WhisperX's loopback-only provider destination, service input constraints and bounded request processing (packages/provider-whisperx-local/src/provider.ts:103-120; services/whisperx/src/hypit_whisperx_service/application.py:52-76).
- Keep provisioning explicit: normal build preflight requires programs to be ready and does not provision them; runtime up is the designated installation/start path (packages/cli/src/main.ts:407-425; packages/cli/src/commands/environment.ts:218-235).
- Preserve release artifact provenance and publication targeting: publish workflow verifies stable version/main ancestry, builds and checks the package, then publishes the prepared artifact (.github/workflows/publish-npm.yml:40-94,107-148).

Some direct working-tree reads returned empty despite nonzero file sizes; git show HEAD:path provided the selected committed source. - External implementations, installed dependency bytes, DNS/proxy settings, dependency-specific telemetry and actual packet destinations were not inspected or contacted. - The word local does not promise offline setup. Documentation explicitly identifies separate Python, package, NLTK, ASR and alignment downloads and inherited network/cache variables; source implements corresponding preparation/model-loading calls. No contradiction was found for that claim (packages/provider-whisperx-local/README.md:66-99; packages/provider-whisperx-local/src/program.ts:128-135; services/whisperx/src/hypit_whisperx_service/resources.py:38; services/whisperx/src/hypit_whisperx_service/engine.py:107-111,126-129).
- Concrete documentation/comment discrepancy: resolveRuntimeExecutable's comment says configured relative paths are rooted at the Runtime Profile root, but the OpenCV caller passes dataRoot. An explicit relative OpenCV pythonExecutable therefore resolves under the effective dataRoot, not necessarily the profile directory (packages/runtime-host-node/src/index.ts:348-350; packages/provider-image-opencv-local/src/deployment.ts:41-44). This is an architecture fact, not a validated vulnerability.
- The direct HypiHub library factory and profile adapter expose different URL validation surfaces; claims about the adapter's HTTPS check must not be generalized to all library callers (packages/provider-hypihub/src/activation.ts:35-40; packages/provider-hypihub/src/provider.ts:59-64,512-530).
- SSH/backdoor absence is not established by the architecture map alone. Static documentation links and README media embeds are not equivalent to a runtime connection. Source tracing in reviewed surfaces found no backdoor; whole-repository line-by-line and dependency/runtime coverage remain incomplete.
- Runtime has four reported slots including root; an additional focused worker spawn returned agent thread limit reached. Parent performed the focused installer/CI/execution investigation itself; independent baseline and architecture reviewers completed.
